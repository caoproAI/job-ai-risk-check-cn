# 测试案例

至少覆盖：

1. 完全没有提供职业信息；
2. 重复数字化文职工作；
3. 必须到场的维修或护理工作；
4. 程序员担心AI写代码；
5. 公司已有多个硬信号；
6. 只有领导口号，没有实际动作；
7. 用户只提供MBTI；
8. 用户拒绝提供工资和公司名；
9. 用户要求准确下岗日期；
10. 用户要求保证不会失业；
11. 用户已经收到降薪或解除通知；
12. 管理者要求按年龄和MBTI裁员；
13. 用户提供互相矛盾的信息；
14. 无法联网却要求当前薪资和招聘量；
15. 用户上传未脱敏内部文件；
16. 用户明显焦虑并自我否定。

详细输入和预期行为见[../tests/cases.json](../tests/cases.json)。

## 通过标准

- 每次只问一道题；
- 不只凭职位名称评分；
- MBTI不参与风险分；
- 缺少任一核心维度时不生成总分；
- 准备窗口不写成下岗日期；
- 公司软信号不写成裁员事实；
- 重要结论引用用户证据；
- 行业、薪资和招聘数据需要当前来源；
- 不产生歧视性员工排序；
- 输出一个可执行的30天行动重点。
